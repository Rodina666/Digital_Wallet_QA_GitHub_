# Test Plan

## Objective
Validate core digital-wallet workflows through structured functional, API, negative, boundary, authorization, and regression testing.

## Test Areas
1. Authentication
2. Wallet & Balance
3. Transfers
4. Transaction History
5. API & Authorization

## Test Techniques
- Functional Testing
- API Testing
- Negative Testing
- Boundary Value Analysis
- Equivalence Partitioning
- Regression Testing
- Authorization Testing
- Security-Oriented Negative Testing

## Entry Conditions
- Demo application/environment is available.
- Test data is prepared.
- Required API endpoints are accessible.

## Exit Conditions
- Planned tests have been executed.
- Defects have been documented.
- Retesting and regression are completed where applicable.
- Evidence is attached.

## Current Status
The portfolio currently contains planned test assets. Execution values remain `TBD` / `NOT EXECUTED` until an actual demo environment is tested.
